== The series

The tebako ecosystem packages applications and runtimes into single
executables whose loading behavior is governed by normative
specifications: the wire format of the package container, the manifest
grammar of a payload, the contract between the loader and a runtime, and
the policies for resolution, caching, jailing, trust, and observability.
Those normative texts live as Markdown files in the product repository,
and an implementer — a runtime factory author, a registry operator, a
feedstock maintainer — has until now read them only as raw Markdown
source, with no rendered document to cite.

The Tebako Specifications (TBK SPEC) series closes that gap. Each
document in the series is one normative text from the repository,
converted to a Metanorma standard document and rendered to HTML and PDF
as a member of a single collection. The document numbering follows the
numbering of the source files: TBK SPEC 02 renders `02-tpkg-wire-format.md`,
and so on. Section numbering, section titles, tables, and code listings
are carried over verbatim, so a reference of the form "spec 06 §4"
resolves identically against the Markdown source and against the
rendered document.

== Source of truth and synchronization

The Markdown files under `docs/spec/` in the `tamatebako/tebako`
repository are the source of truth for every document in the series.
This series is their rendered form; the AsciiDoc twin of a specification
is derived from the Markdown and never edited independently. The
Markdown sources themselves are not modified by the rendering process.

Each rendered document records the blob SHA of the Markdown file it was
converted from in a comment line of the form
`// source: docs/spec/NN-name.md @ <sha>`. The drift gate at
`docs/spec-site/tools/sync.rb` recomputes the blob SHA of every
referenced Markdown source and compares it with the recorded value. The
gate exits with status 0 when every rendered twin is current, and exits
1 naming the drifted documents when a Markdown source has moved without
its rendered twin being updated. A continuous-integration job runs the
gate on every pull request that touches `docs/spec/`, so a specification
edit cannot land without its rendered twin following it.

The conversion from Markdown to AsciiDoc is performed and reviewed by
hand; the gate does not regenerate document content. After a
specification edit has been carried into its twin and reviewed,
`ruby docs/spec-site/tools/sync.rb --sync` updates the recorded SHAs to
bless the new state.
