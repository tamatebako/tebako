A payload author virtualizing an application on tebako must answer three
questions, and today each is answered by hand-rolled one-off diagnostics
(the incident-13 msys dogfood chain: four CI rounds of pass:c,q,a,m,p[`eprintln`] gates
and in-probe bisection to name one Windows loader failure):

. *Discovery* — what does my application touch, so what must I
declare? (mounts, pass:c,q,a,m,p[`needs:`], pass:c,q,a,m,p[`materialize:`], entrypoints)
. *Diagnosis* — my packaged application fails; which hop failed?
(mount → manifest → resolve → materialize → OS bind)
. *Coverage* — is anything my application does NOT virtualized?
(raw syscalls, unpatched IATs, loader-internal probes — the escapes)

This spec defines one substrate and three front-ends:

* *The interception bus* (§2): every tebako interception point emits
one structured event. The bus lives in the Rust pass:c,q,a,m,p[`tfs`] crate — the
shipping VFS implementation on every platform — so it is
cross-platform and runtime-independent by construction: events name
syscall/loader-level facts (paths, verdicts, errnos), never
language facts. Ruby, Julia, and Python payloads are equally covered
because every runtime bottoms out at the same libc/loader boundary
the bus instruments.
* *pass:c,q,a,m,p[`tebako trace run`]* (§4): discovery — collect a run's events and
emit a suggested manifest.
* *pass:c,q,a,m,p[`tebako trace explain`]* (§5): diagnosis — replay a capture into
the hop chain and name the first red hop.
* *pass:c,q,a,m,p[`tebako trace cover`]* (§6): coverage — correlate the inside stream
with an outside capture and report what escaped.


[%unnumbered]
== 1. Laws

. *Observability never gates.* A trace-channel failure degrades to a
loud stderr note; the payload run proceeds and its exit code is
unaffected. A tracer must never become a failure mode.
. *Runtime-independent.* Events name OS-level facts only. No event
may carry a language-runtime concept (a gem, a module, a Julia
package) — runtimes are payloads; the bus sits below them.
. *Cross-platform inside; layered outside.* The inside stream is
identical on linux, macOS, and windows. The outside view is the
three-layer producer model (§6.1): the libc boundary is retrace's on
BOTH platforms (preload on POSIX; the preload-msvc / preload-mingw
inline-hook backends on windows, retrace ADR-0009); kernel-level
producers (ptrace, eBPF, ETW/procmon) join ONLY as retrace-shaped
JSON, via bridges or offline converters (§6.2). Every outside source
is an import format, never a runtime dependency.
. *No shell-outs.* Captures are files parsed in-process. Arming or
reading a trace never spawns a tool (spec 00 invariant 1).
. *The correlation law.* The inside stream can never prove its own
completeness: an escape is invisible from inside by definition
(macOS 15's dyld rpath probes never reach the interposed pass:c,q,a,m,p[`open`] —
the exec-closure walk exists because of this). "What isn't tebako
intercepting" is answerable ONLY by subtracting the inside stream
from an outside capture — and only up to the outside capture's own
layer (§6.1).
. *MECE with spec 23 §8.* The pass:c,q,a,m,p[`record`] policy mode already owns
host-path needs discovery (the audit journal → `tfs needs
--from-journal`). This spec does not re-invent it: the jail channel
of the bus IS that journal, formalized; §4's discovery extends the
draft to the axes §8 does not cover (pass:c,q,a,m,p[`materialize:`], entrypoints,
runtime deps).
. *Human gate.* A generated suggestion never edits a manifest by
itself (spec 23 §8's law, unchanged).


[%unnumbered]
== 2. The interception bus (pass:c,q,a,m,p[`tfs::trace`])

*Emission points* — exactly the interception points the driver/TFS
already implements, one event per decision:


[cols="<,<,<",options="header"]
|===
| op | emitted where | verdict values
| pass:c,q,a,m,p[`mount`] | mount table insert/remove | pass:c,q,a,m,p[`ok`] / pass:c,q,a,m,p[`error:<errno>`]
| pass:c,q,a,m,p[`open`] / pass:c,q,a,m,p[`stat`] | path dispatch (spec 11) | pass:c,q,a,m,p[`image:<mount>`] / pass:c,q,a,m,p[`host`] / pass:c,q,a,m,p[`denied:<rule>`] / pass:c,q,a,m,p[`error:<errno>`]
| pass:c,q,a,m,p[`dlopen`] | pass:c,q,a,m,p[`dlmap2file`] / pass:c,q,a,m,p[`dlalias2file`] | pass:c,q,a,m,p[`materialized:<host-path>`] / pass:c,q,a,m,p[`host`] / pass:c,q,a,m,p[`error:<errno>`]
| pass:c,q,a,m,p[`exec`] / pass:c,q,a,m,p[`spawn`] | exec routing (spec 17/22) — one routing decision, two syscall surfaces: pass:c,q,a,m,p[`exec`] is the execve surface (process replacement), pass:c,q,a,m,p[`spawn`] the posix_spawn surface (a child is created — the correlator's process-tree signal) | pass:c,q,a,m,p[`routed:<entry>`] / pass:c,q,a,m,p[`host`] / pass:c,q,a,m,p[`error:<errno>`]
| pass:c,q,a,m,p[`materialize`] | exec-cache extraction | pass:c,q,a,m,p[`ok:<host-path>`] / pass:c,q,a,m,p[`cache-hit`] / pass:c,q,a,m,p[`error:<errno>`]
| pass:c,q,a,m,p[`jail`] | policy bind / check (spec 08, 23 §8) | pass:c,q,a,m,p[`allow:<rule>`] / pass:c,q,a,m,p[`deny:<rule>`] / pass:c,q,a,m,p[`record`]
| pass:c,q,a,m,p[`resolve`] | the driver's pass:c,q,a,m,p[`--tebako-image <path>:<slot>:<mount>`] resolution (trailer probe → whole file or slot region — the payload/slot identity the correlator matches outside reads against). *PLANNED:* the L3 runtime/payload cache resolution (tebako-resolve — loader-side, outside the runtime process; its channel story lands with the phase that needs it) | pass:c,q,a,m,p[`whole`] / pass:c,q,a,m,p[`slot:<n>`] / pass:c,q,a,m,p[`error:<errno>`] — PLANNED L3 half: pass:c,q,a,m,p[`cache`] / pass:c,q,a,m,p[`fetched`] / pass:c,q,a,m,p[`error`]
|===


The pass:c,q,a,m,p[`dlopen`] event's pass:c,q,a,m,p[`detail`] carries the closure walk as structure —
the parsed format, the dep list, each dep's resolve verdict
(pass:c,q,a,m,p[`materialized`] / pass:c,q,a,m,p[`host-system`]) — what incident 13's round 4 added as
pass:c,q,a,m,p[`eprintln`] lines. Those gates convert to events; pass:c,q,a,m,p[`TEBAKO_DEBUG_TFS`]
remains as the human-readable degraded view over the same emission
points.

*Arming.* pass:c,q,a,m,p[`TEBAKO_TRACE=<host-path>`] (env) or `--tebako-trace
<host-path>` on the driver argument grammar (spec 17 — the env-scrubbed
handoff rides the argument, the lesson of incident 13 round 5). The flag
is an additive optional driver argument: spec 17's grammar extends by
option, never by version bump (the trailer-flags rule, spec 02). Both
set: the argument wins. The channel is opened and pre-registered at
driver boot, before any mount — writes are append-only, process-internal,
and NEVER policy-gated (the journal channel's discipline,
pass:c,q,a,m,p[`crates/tfs/src/journal.rs`], already proven under pass:c,q,a,m,p[`deny`]).

*Cost when off.* Disarmed, an emission point is one
pass:c,q,a,m,p[`Option::is_none()`] branch. The bus compiles into the runtime/driver
side only; the bootstrap's < 3 MB size gate is untouched (spec 00
invariant 2).

*Children.* Spawned children inherit the armed channel by fd
inheritance where the platform allows (POSIX); on windows each child's
driver re-opens the same path for append (the record mode's
re-derivation, spec 23 §8). All writers append atomically; events may
interleave — every event carries pass:c,q,a,m,p[`pid`]/pass:c,q,a,m,p[`tid`] so the front-ends regroup.


[%unnumbered]
== 3. The event envelope (schema v1)

One JSON object per line (JSONL; streamable, diffable, robust to a
crashed tail). Authored configs stay YAML (invariant 6); the event
STREAM is telemetry and is JSON. The versioned schema lives at
pass:c,q,a,m,p[`docs/spec/schemas/trace-event.yaml`] (lands with phase T1); the
normative shape:


[source,yaml]
----
v: 1                    # envelope version — additive only, never bumped
ts: <rfc3339μs>         # driver clock
pid: <int> ; tid: <int>
op: <table §2>
path: <vfs-or-host path, exactly as dispatched>
verdict: <table §2>
detail: { ... }         # per-op: dlopen deps, jail rule, exec argv0, …
dur_us: <int>           # the interception's own cost
errno: <int, optional>  # when verdict names an error
----

CI validates every emitted event against the schema (a property test
drives the whole op matrix and validates the stream).


[%unnumbered]
== 4. pass:c,q,a,m,p[`tebako trace run`] — discovery

Runs an application composition under pass:c,q,a,m,p[`policy: record`] with the bus
armed, then synthesizes a *suggested manifest* — a commented YAML
fragment, never applied (law 7):

* host reads → pass:c,q,a,m,p[`needs:`]/pass:c,q,a,m,p[`jail:`] ro grants (this half is spec 23 §8's
generator, unchanged — the bus's jail channel feeds it);
* host writes → rw grants (strongest-observed-op wins, §8's rule);
* a VFS-resident file read through a RAW host fd (a native library's
own pass:c,q,a,m,p[`fopen`] — the exec-cache answer consumed it) → a pass:c,q,a,m,p[`materialize:`]
candidate — the sassc class-R case, caught automatically instead of
discovered by a failing import;
* an in-image pass:c,q,a,m,p[`dlopen`] whose deps all resolve in-image → a NOTE
"closure-covered — nothing to declare";
* a spawned host-absolute executable → an entrypoint/runtime-dep note;
* floor, store, and exec-cache paths are excluded (§8's exclusion law).

Output: the draft fragment on stdout (or pass:c,q,a,m,p[`--out`]), each entry carrying
its pass:c,q,a,m,p[`why:`] evidence line (pass:c,q,a,m,p[`observed: <n> events, first at <ts>`]). The
author reviews, flips ro↔rw, deletes noise, fills pass:c,q,a,m,p[`why`].


[%unnumbered]
== 5. pass:c,q,a,m,p[`tebako trace explain`] — diagnosis

Replays a capture (or a live run's stream) into the hop chain —
mount → manifest read → resolve → materialize → OS bind — and prints
the first hop whose verdict is red, with the signature table seeded
from the incident corpus:


[cols="<,<",options="header"]
|===
| signature in the stream | named hop
| no pass:c,q,a,m,p[`mount`] event for the env image + prelude-class child stderr | env image never mounted (handoff env lost)
| pass:c,q,a,m,p[`dlopen`] verdict naming the OS loader's module-not-found (windows error 126; the POSIX pass:c,q,a,m,p[`dlopen`] ENOENT analogue) with every dep pass:c,q,a,m,p[`materialized`]\|pass:c,q,a,m,p[`host-system`] | the OS bind itself — bisect candidates printed
| pass:c,q,a,m,p[`jail`] pass:c,q,a,m,p[`deny`] immediately preceding a dependent pass:c,q,a,m,p[`open`] error | policy denial (the EACCES class)
| pass:c,q,a,m,p[`materialize`] pass:c,q,a,m,p[`error`] | exec-cache write failure
|===


The table lives in data (a YAML map in the CLI crate), extended as
incidents teach new signatures — never hard-coded into the bus.


[%unnumbered]
== 6. pass:c,q,a,m,p[`tebako trace cover`] — coverage

The escapes report (law 5). Inputs: an inside capture (the bus) and an
outside capture of the same run.


[%unnumbered]
=== 6.1 The three-layer model (normative)


[cols="<,<,<,<",options="header"]
|===
| layer | POSIX | windows | who sees it
| inside the VFS | the tfs bus (§2) | the tfs bus (§2) | tebako
| libc boundary | retrace preload | retrace inline hooks (preload-msvc / preload-mingw, retrace ADR-0009) | retrace — both platforms
| kernel syscall | retrace ptrace backend; strace → strace2retrace (converter, §6.2); eBPF bridge | ETW / procmon (via converter, §6.2) | kernel tracers
|===


Escapes split into two classes at the libc boundary:

* *libc-routed escapes* — the application called pass:c,q,a,m,p[`open(2)`] /
pass:c,q,a,m,p[`CreateFileW`] directly, below tebako's interposition but through
libc. Visible to retrace on BOTH platforms today.
* *sub-libc escapes* — raw pass:c,q,a,m,p[`syscall(2)`] / pass:c,q,a,m,p[`NtCreateFile`],
loader-internal probes (the macOS dyld rpath class). Invisible to
libc hooks by construction; only a kernel-layer producer sees them.

A coverage report is only as strong as its outside capture's layer: a
libc-boundary capture certifies libc-routed escapes only; sub-libc
certification requires a kernel-layer capture. The report MUST name the
producing layer of its outside input.


[%unnumbered]
=== 6.2 The outside format — retrace-shaped JSON (SSOT: retrace)

The outside capture format is the retrace trace document, owned and
versioned by the retrace project (riboseinc/retrace). Tebako never
authors a competing outside format. Every producer normalizes INTO that
shape; the correlator stays format-uniform:

* *retrace preload / inline hooks* — native JSON output today
(one JSON array document per capture).
* *retrace ptrace backend* — native, POSIX kernel layer.
* *eBPF bridge* (pass:c,q,a,m,p[`ebpf-bridge/`]) — emits retrace-shaped JSON.
* *procmon / ETW* (windows kernel layer) — an OFFLINE converter
(procmon CSV/XML export → retrace JSON), the same decision as the
Frida/eBPF bridges: producers normalize into the format, never the
reverse. The converter ships in the tebako CLI as an import verb
(pass:c,q,a,m,p[`tebako trace import procmon <csv>`]), pure Rust, in-process (law 4).


[%unnumbered]
=== 6.3 The correlator — self-contained Rust

pass:c,q,a,m,p[`tebako trace cover`] implements the correlation IN the tebako CLI, in
safe Rust: canonicalize host paths on both sides (same atoms as spec 23
§8's generator); subtract every outside-observed op that an inside
event already accounts for; the remainder is the escapes list, grouped
by surface class (fs / exec / dlopen / spawn), with a per-class
coverage percentage and the producing layer named (§6.1). Exit code 0 =
no escapes, 1 = escapes found — CI-gateable. Intentionally-unserved
surfaces (documented passthroughs, e.g. the platform floor) are
declared in the composition so the report separates KNOWN-UNSERVED from
ESCAPE.

*The shipped surface (phase T3, the correlator half).*


[source]
----
tebako trace cover --inside <tfs.json|jsonl> --outside <retrace.json>
                   --prefix <path> [--pid N] [--window SECS]
                   [--exclude-probes] [--json] [--layer libc|kernel]
----

* *stdout is the golden contract*: one
pass:c,q,a,m,p[`escape <path> func=<f> tid=<t> pid=<p> class=<probe|read|write|none>`]
line per escape (retrace's report grammar since its v2.9.0), or
retrace's escape array under pass:c,q,a,m,p[`--json`]. Byte-compared in CI against
retrace's shared golden tree (pass:c,q,a,m,p[`tools/correlate/golden/`], copied
byte-verbatim to pass:c,q,a,m,p[`crates/tebako-cli/tests/fixtures/correlate/`]) —
every case, stdout bytes and exit code. Nothing else ever writes
stdout for this subcommand (the version banner rides stderr).
* *stderr* (outside the golden contract) carries the summary
(pass:c,q,a,m,p[`inside=N entries, M paths; prefix=P; escapes=E`]), the escapes
grouped by surface class with per-class coverage percentages, and the
producing layer named by pass:c,q,a,m,p[`--layer`] (default pass:c,q,a,m,p[`libc`] — §6.1's honesty
rule: the report certifies its named layer only; sub-libc escapes are
UNCERTIFIABLE under a libc-boundary capture).
* *Exit codes* are retrace-correlate's: 0 no escapes, 1 escapes
found, 2 usage or I/O error.
* *The kernel is retrace's* (the pass:c,q,a,m,p[`retrace-correlate`] port): the
tolerant stream scan (array document / JSONL / truncated tail),
any-depth path extraction, NT-form normalization (pass:c,q,a,m,p[`\??\`, `]//?/`,
pass:c,q,a,m,p[`\\?\`, the `]\Device\HarddiskVolumeN` drive guess), drive-letter-
insensitive path comparison with a case-SENSITIVE component-boundary
prefix test, pid/time-window coverage (a pid-less entry is a
wildcard; the bus's string pass:c,q,a,m,p[`ts`] never feeds pass:c,q,a,m,p[`--window`] — window mode
takes retrace-shaped inside captures with numeric pass:c,q,a,m,p[`time`]), the
name-keyed probe/write classification (a NAME-NOT-FOUND probe on an
unserved under-prefix path IS an escape — existence is information),
one escape per outside entry (the first under-prefix uncovered path
in field order), pass:c,q,a,m,p[`--exclude-probes`] for the jail-grant policy.
Documented deviations, error paths only: a non-numeric
pass:c,q,a,m,p[`--pid`]/pass:c,q,a,m,p[`--window`] and an unknown pass:c,q,a,m,p[`--layer`] are named usage errors
(exit 2) where upstream's atol/atof silently read 0 (spec 00 law 9).

The correlator is tebako-owned because the invariants leave no other
home: invariant 1 (no shell-outs in shipped artifacts) forbids invoking
a retrace binary; invariant 3 (C/C++ only in dwarfs-t) forbids linking
one. The correlation kernel (normalize + set difference + threshold) is
small and pure. If the retrace project ships its own
pass:c,q,a,m,p[`retrace-correlate`] for the generic market, the two implementations
assert parity on shared golden fixtures in CI — invariant 10's parity
escape hatch: the FORMAT is retrace's single source; the ALGORITHM has
two implementations that must agree. (retrace's pass:c,q,a,m,p[`retrace-correlate`]
landed ahead of this phase — the golden tree above is that parity
hatch, exercised.)

[%unnumbered]
== 7. Testing and gates

* Golden fixtures: the incident-13 dogfood captures (real pass:c,q,a,m,p[`[tfs\]`]
streams) converted to the schema must round-trip through the
validator and through pass:c,q,a,m,p[`explain`] (whose red hop must match the
incident's hand-derived answer).
* Property: driving the public tfs op matrix emits exactly one
schema-valid event per op.
* Correlator: synthetic inside/outside pairs with deliberate escapes —
a libc-routed fixture (a direct pass:c,q,a,m,p[`fopen`] below the interposition)
under a retrace preload capture, and a raw-pass:c,q,a,m,p[`syscall(2)`] fixture
binary (built by CI, not shipped) under a KERNEL-layer capture —
must be caught at 100%. The raw-syscall fixture paired with only a
libc-boundary capture must report the escape as UNCERTIFIABLE, not
as covered (§6.1's honesty rule).
* Converter: a procmon CSV fixture converts to retrace-shaped JSON the
correlator consumes identically to a native retrace capture.
* Parity (when pass:c,q,a,m,p[`retrace-correlate`] lands upstream): the shared golden
fixtures produce identical escapes reports from both correlators.
* The factory's msys dogfood converts from pass:c,q,a,m,p[`TEBAKO_DEBUG_TFS`] gates to
the bus as phase T1's dogfood — the harness stops hand-rolling
diagnostics.
* Size/hygiene: bootstrap gate untouched; no new dependencies outside
